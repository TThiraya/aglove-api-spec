ข้อควรรู้

  • สร้างคำสั่งซื้อภาคสมัครใจ (VMI) เป็นตัวหลัก พร้อมสร้าง พ.ร.บ. (CMI) แบบ optional ผูกกันด้วย GroupOrderNo/RelationOrderNo — ไม่ส่ง Package มา = ได้ VMI อย่างเดียว, CMIOrder จะเป็น [] โดยไม่ error
  • ลำดับ commit คือ พ.ร.บ. ก่อน แล้วค่อย VMI — และไม่อยู่ในtransaction เดียวกัน ถ้า VMI commit fail หลัง CMI สำเร็จแล้ว จะเหลือ CMI กำพร้า (ErrorCode D90218091)
  • PriceCMI/PriceVMI คำนวณจากฝั่ง VMI แล้ว copy ไปใส่ CMI เสมอ ไม่ใช่ทางกลับกัน
  • Package.AgentCode ถูก overwrite ด้วยรหัส {AgentType}{AgentID} ของผู้เรียกเสมอ ไม่ว่า client จะส่งอะไรมา
  • ไม่มี Branch-user check บน endpoint นี้ (เหมือน create แบบเดี่ยว)
  • endpoint นี้ใช้ VMIRequest.CompanyCode + ClassIds (พหูพจน์) — คนละชุด field กับ create ที่ใช้ CompanyId + ClassId (เอกพจน์)
  • ⚠️ VMIRequest ที่ส่งเข้า endpoint นี้ต้อง copy มาจาก response ของ POST /ComparePrice/package/search (field VMIRequest ของ package ที่เลือก) แบบทั้งชุดตรงๆ ห้ามประกอบเองจาก field กระจัดกระจาย/order อื่น แม้ค่าจะดู "ถูกต้อง" ทีละ field — พลาดแล้วได้ ErrorCode D9021405 "Package does not exist." (ยืนยันจากทดสอบจริง 20/08/2026 — พบสาเหตุจาก CarTypeCode ที่ต้องเป็น "110" ไม่ใช่ "1.10" และ ClassId/CompanyId/AgentCode ที่ต้องมีค่าตรงกับที่ search คืนมา ไม่ใช่ปล่อย null)
  • ⚠️ CarDetailsExtension.LicenseProvinceID/ColorID ต้องเป็น GUID จริงที่มีอยู่ในระบบเท่านั้น — ถ้าไม่มีจริงจะได้ ErrorCode D9021811 (message แยกตาม field: "License province does not exist." / "Car color does not exist.") ตัวอย่าง Request ด้านล่างนี้เป็นข้อมูลจริงที่ยิงผ่านสำเร็จทั้งหมด (ไม่มี field ไหนเป็นค่าจำลอง/placeholder) ใช้อ้างอิง copy ได้ตรงๆ
