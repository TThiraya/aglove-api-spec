ข้อควรรู้

  • endpoint จริงมีตัวเดียว (https://wsapidev.indara.co.th/pogtws_sit/service.asmx?op=CallTHI) แยก operation ด้วยค่า rpcNumber ใน body ไม่ใช่คนละ URL
  • รูปแบบจริงบน wire คือ SOAP 1.1 (POST, Content-Type: text/xml) ไม่ใช่ JSON — body คือ SOAP envelope ที่มี กับ (XML string ใน CDATA) ตารางด้านล่างแสดงฟิลด์ที่อยู่ *ข้างใน* inStr/CallTHIResult เพื่อให้อ่านง่าย ไม่ใช่ตัว JSON จริง
  • rpcNumber Fixed = 108 สำหรับ CMI (ออก พ.ร.บ.) — เอกสาร/Postman เก่าบางที่ใช้ 108CAL แต่ field spec ทางการ v1.7.0 ไม่มี CAL suffix ให้ใช้ 108 เฉยๆ
  • ⚠️ เติม MOBILE_NO และเติมค่า TEL_NO/DELIVERY_TITLE/DELIVERY_FIRSTNAME/DELIVERY_LASTNAME แล้ว — ตัวอย่าง Postman ต้นฉบับที่ Indara ส่งมาขาด/ปล่อยว่างฟิลด์ Mandatory เหล่านี้ ยังไม่เคยทดสอบว่า Indara enforce จริงหรือไม่
  • PLAN_CODE/CAR_COLOR/PLATE_TYPE/TITLE ต้อง resolve จาก Master sheet ของ Indara ก่อนส่ง (ดูเอกสารแนบ)
  • response คืนเบี้ย/อากร/VAT/ยอดรวมหลังออกกรมธรรม์แล้วเท่านั้น — ไม่มี API แยกคำนวณเบี้ยก่อนออกกรมธรรม์
  • AGENT_CODE/USER_ID/PASSWORD_AGENT ในตัวอย่างนี้เป็น test account ของ Indara เอง (มาจากเอกสารอ้างอิงที่ Indara ส่งให้) — 724 ต้องใช้ credential จริงที่ Indara ออกให้ 724 โดยเฉพาะ (ขอจาก PM ผ่านช่องทางที่ปลอดภัย ไม่ publish ไว้ในเอกสารนี้)
  • Production endpoint: https://wsapi.indara.co.th/pogtws/service.asmx?op=CallTHI (credential Production คนละชุดกับ UAT — ขอจาก PM)
  • อ้างอิงจาก field spec ทางการของ Indara รุ่น v1.7.0 (ออก 2026-08-03)
