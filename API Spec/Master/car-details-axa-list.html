POST/Master/car-details/axa/list

ข้อควรรู้

  • ใช้แปลงรถที่เลือกจาก car-master 724 (ยี่ห้อ/รุ่น/ขนาด/ประเภทการใช้งาน) เป็น CMI VehicleKey ของ AXA สำหรับออกกรมธรรม์ พ.ร.บ.
  • ไม่ต้องส่ง Authorization header — endpoint นี้เปิดให้เรียกได้โดยไม่ต้อง login (ต่างจาก endpoint อื่นของ AgentLove ส่วนใหญ่)
  • ฟิลด์ทั้ง 5 ที่ใช้จริง (UseCarCode/CarTypeCode/CarCategoryID/CarBrandID/CarModelID) เป็น optional ทั้งหมด — AND เข้า query เฉพาะตัวที่ไม่ว่าง
  • CarSalesYear รับค่าได้แต่ไม่ได้ใช้กรองข้อมูลเลย (เคยกรองได้แต่ column ถูกตัดออกจาก view แล้ว) — แต่ยังมีผลต่อ cache key ฝั่ง server
  • ⚠️ ห้ามส่ง {} (ทุกฟิลด์ว่าง) — จากการทดสอบทำให้ query กวาดข้อมูลทั้ง view (~35.6k แถว) จน DB timeout ที่ ~30 วินาที แล้วตอบกลับเป็น A225804 (เข้าใจผิดว่า 'ไม่พบข้อมูล' ได้) ให้ส่งอย่างน้อย UseCarCode+CarTypeCode เสมอ
  • ⚠️ .Clean() ฝั่ง server ไม่ตัดช่องว่างนำหน้า (leading space) เช่น " PERSONAL" จะหาไม่เจอ (ตกไปที่ A225804) ทั้งที่ "PERSONAL " (ช่องว่างต่อท้าย) หาเจอปกติ — ควร trim ค่าก่อนส่งเสมอ
  • ไม่พบข้อมูล (0 แถว) และ DB/Dapper error แยกไม่ออกจาก response — ทั้งคู่ตอบเป็น A225804 พร้อม ErrorMessage ต่างกัน
  • ผลลัพธ์เป็น SELECT DISTINCT ไม่มี ORDER BY — ลำดับแถวไม่แน่นอน
  • คืนเฉพาะแถวที่ CMI_VehicleKey ไม่เป็น null เท่านั้น (WHERE CMI_VehicleKey IS NOT NULL)
  • ผลลัพธ์ที่สำเร็จถูก cache ไว้ 3 ชั่วโมง โดย cache key คำนวณจาก request แบบดิบก่อน .Clean() — เว้นวรรค/CarSalesYear ต่างกันทำให้ cache แตกกันแม้ query จะเหมือนกันในทางปฏิบัติ
  • ErrorCode ที่พบ: A225203 (ความยาวฟิลด์เกิน 50 ตัว — Message เป็น null, Options.Parameter บอกชื่อฟิลด์), A225804 (ไม่พบข้อมูล/DB error), A225999 (unhandled exception รวมถึง body ว่าง/parse ไม่ได้)
  • ถ้าไม่ส่ง body เลย (ไม่มี Content-Length) จะได้ HTTP 411 แบบ HTML ไม่ใช่ envelope ปกติ — ต้องส่ง body เป็น JSON เสมอแม้จะเป็น {}
