POST/SKRegister/register/create

ข้อควรรู้

  • Base URL dev: https://api-cnt-aglove.724insure.net — ทดสอบจริงเมื่อ 03/09/2026
  • ทุก endpoint ตอบ HTTP 200 เสมอ แม้เป็น error — ต้องอ่านสถานะจริงจากฟิลด์ Status (200/400) และ ErrorCode ใน body
  • ErrorMessage ของ error กลุ่ม validation มีส่วนต่อท้าย (Parameter 'ชื่อฟิลด์') ติดมาด้วยเสมอ เช่น "IDCard cannot be empty. (Parameter 'IDCard')" — ห้ามเอาไปแสดงผลให้ผู้ใช้ตรง ๆ ให้ map จาก ErrorCode เอง
  • ไม่ต้องใช้ token (anonymous)
  • PrefixID ของบุคคลธรรมดาต้องดึงจาก POST /Master/prefix/list body {"IsPerson": true} (169 รายการ) — ถ้าเรียกด้วย body ว่างจะได้เฉพาะคำนำหน้านิติบุคคล 21 รายการ ซึ่งใช้กับ flow นี้ไม่ได้
  • CR-8: ส่ง BranchCode มาด้วยได้ ระบบจะ resolve เป็น SKBranchRegisterID + BranchCode บน order — สาขาที่ใช้ไม่ได้จะถูกเมินเงียบ ๆ (ทั้งสองฟิลด์เป็น null) ไม่บล็อกการสมัคร
  • BranchCode ที่เก็บมาจากเรคคอร์ดที่ resolve ได้ ไม่ใช่ค่าที่ส่งมา
  • OrderNo ยังเป็น null ตอนนี้ — ถูกกำหนดทีหลังใน flow
  • Email ถูกบันทึกจริงแต่ไม่ถูก validate (ทั้ง empty-check และ length-check ถูก comment ไว้ใน source)
  • EKYCSecretCode และ AccessToken ถูกล้างเป็น "" ก่อนส่งกลับเสมอ
